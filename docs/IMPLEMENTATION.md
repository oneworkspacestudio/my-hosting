# My Hosting implementation and acceptance plan

## Reconnaissance, 18 October 2026

Canonical suite: https://github.com/oneworkspacestudio/one-workspace . Its
schema-1 catalog/integration-2 contract owns executable hashes, ports, OIDC
callbacks, protected private data, lifecycle, optional app selection, and updates.
MyAccounts uses discovery, authorization code + PKCE and nonce. Owner identity
must come from the manager's configured subject, never the first internet login.
The seamless sign-in registry and global logout must include Hosting.

This is an **original repository**, not a GitHub fork. Evaluated upstreams:

| Upstream | Findings | Decision |
|---|---|---|
| [Coolify](https://coolify.io/docs/start-with-self-hosted) | Actively maintained, Apache-2.0; Linux/Docker deployment architecture and PHP control plane | Forking would preserve infrastructure this Windows/no-Docker product cannot use |
| [Dokploy](https://github.com/Dokploy/dokploy) | Active; Docker Swarm/Traefik and PostgreSQL; includes separate proprietary terms | Does not fit native Caddy/Go/SQLite or the intended dependency boundary |
| [pico](https://github.com/picosh/pico) | Go SSH publishing services; different authentication/deployment model | Not a reusable Node process/build control plane |
| [Caddy](https://github.com/caddyserver/caddy) | Apache-2.0, native Windows artifacts, automatic HTTPS | Managed dependency; no cosmetic fork |

Brand sources: suite `internal/branding/icons`, portal/navigation CSS, Chat's
Workspace web skin. Compare Drive (layered indigo/mint), Notes (silver details),
and Chat (indigo/mint gradients). Reuse exact gradient stops and portal semantic
colors; no Netlify assets. UI is React/TypeScript/Vite, authored in AUI with the
write-aui-ui skill and generated by pinned @codedia/parser.

## Architecture decisions

- SQLite WAL with versioned migrations; metadata, immutable job snapshots,
  memberships, idempotency keys and audit chain. Ordinary release/log directories.
- A single managed Caddy per Hosting installation, with ownership/lock markers.
  Never adopt an external listener. Disable its unauthenticated admin API;
  validate each configuration and use its authenticated atomic load API on
  loopback (mutual TLS, dedicated private CA/client, no system trust changes).
  Probe the deploy header before committing a traffic switch. Dashboard and
  user-deployed content always use separate origins.
- Pin verified official Caddy and Node artifacts. Static ZIPs need no Node.
  Node majors have separate shared read-only runtime copies. No inherited
  Workspace/GitHub/OIDC credential environment for project processes.
- Initial scope is trusted administrators/projects. Restricted Windows tokens,
  protected per-project ACLs and Job Objects are defense in depth, not a VM or
  a claim of safe untrusted multi-tenant hosting. Fail closed on SYSTEM builds,
  missing ACL support or unavailable restrictions. Developers can deploy approved
  projects; only administrators configure commands/credentials.
- HTTPS requires verified DNS and public reachability; show pending/actionable
  status until real certificate/health evidence. Local preview works separately.
- GitHub REST source archives pinned to resolved immutable SHAs, no global Git
  prerequisite. Fine-grained PAT is a documented initial option. HMAC webhooks,
  payload deduplication and branch allowlists; no credentials in browser bundles.
- Main launcher embeds the UI; Caddy and Node are additional managed processes.
  Private state needs NTFS. Public source/artifacts are staged on I: after E:
  dependency corruption; both external exFAT volumes need filesystem attention.

## Verified progress after the initial checkpoint

Full native Go suite passed on18October with pinned official Caddy2.11.7 and
Node24.22.0. Added real static publication, preview routing, multiple production
switches, rollback and encrypted backup/restore; real Node publication, restart,
host/cross-project/immutable artifact negative probes and unauthenticated Caddy
control rejection. Existing auth/roles/CSRF, unsafe archives, redaction, immutable
queued environment/restart and audit checks remain passing. Browser first-run,
project wizard, navigation, light/dark and mobile checks passed earlier.

The owner selected the free tunnel design: exact `my-site-sites.m8e.co.uk`
hostnames, with `deploy-ID--my-site-sites.m8e.co.uk` previews. Generic installations
use their own connected zone. No router/paid-certificate changes were made.
Exact CNAME/tunnel routes are provisioned without replacing conflicting records
or other ingress settings. Real public HTTPS with the matching deployment header
was verified at the isolated synthetic launch-check site, including in Chrome.
Fresh public DNS verification fixes stale local wildcard/NXDOMAIN false failures.

This is progress, not completion of the remaining gates below: full real
MyAccounts/installer, Next/Nuxt builds, webhook and cancellation/recovery matrix,
retention/canonical domains, release packaging/compatibility and service/reboot
acceptance still require evidence. Do not publish a stable/complete claim.

## Gates (not yet completed)

1. Server, SQLite migrations/auth/roles, branded complete dashboard.
2. ZIP/GitHub static source, atomic Caddy deployment and rollback.
3. Restricted Node builds/runtime manager, Express, Next standalone, Nuxt Nitro.
4. All deploy actions, cancellation/recovery, previews, streaming logs/audit.
5. Domains, secrets, retention, backup/restore and negative security tests.
6. Suite catalog/OIDC/seamless navigation/icons/build/docs integration.
7. Local automated tests and isolated browser/integration checks; fresh install,
   reboot/service/another-machine recovery checks must be explicitly evidenced.
8. Publish app then paired suite only after critical gates pass. No Actions.

Do not turn incomplete acceptance into a stable release or claim a fork.
